# DiPlay v0.3.1 — 媒体音频焦点独占、无线后台会话保活、尺寸防黑边重算及蓝牙热点容错自愈

## 更新

- **媒体音频焦点独占模式（高级设置）**（Issue #290）：
  - 针对部分车机（如部分定制 Android 系统）在 `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` 模式下会将声音永久闪避并锁死为静音的问题，在「高级设置 → 音频焦点」中新增「媒体音频焦点独占」选项；
  - 开启后，媒体流请求将改为 `AUDIOFOCUS_GAIN`，确保在这类车机上正常输出音乐与媒体声音；默认保持关闭，不影响原有车机多音源混音逻辑。
- **无线 CarPlay 后台热切与会话平滑保活**（Issue #316）：
  - 优化无线 CarPlay 连接链路在应用切换到后台时的保活与接管逻辑；
  - 避免切出应用瞬间误杀连接通道，切回前台时无缝恢复控制与流传输，大幅降低切回时的重连延迟。
- **倒车退出图层与多轮尺寸自适应重算防黑边**（Issue #290）：
  - 解决倒车摄像头退出或首次进入 CarPlay 时，因多轮布局计算中途消费了监听器导致尺寸计算停留在中间态的问题；
  - 将尺寸稳定重算监听器贯穿 3 秒稳定窗口，并在每次尺寸变化时动态重新计算，彻底消除黑边与底部黑条异常。
- **Wi-Fi Direct 不支持时快速阻断引导与诊断细化**（Issue #331, #285）：
  - 针对硬件/系统不支持 Wi-Fi Direct 的车机设备，在启动阶段快速失败并提供明确的局域网或有线连接引导提示，避免无意义的重试超时；
  - 并在诊断日志中细化记录 USB Root 权限授予失败的具体原因（如缺少 su 二进制或授权被拒绝）。
- **蓝牙 RFCOMM / DLC 失败剔除与热点重连自愈**（Issue #165, #313）：
  - 修复 PN 发送失败后 RFCOMM 层残留导致重连循环重用坏死链路的问题，失败后主动剔除缓存层；
  - 针对原厂车载热点模式下首个客户端连接时可能遗留的蓝牙状态异常，增加按需单次蓝牙复位重试机制。
- **应用生命周期安全加固**（Issue #310）：
  - 修复深色模式切换在 Activity 销毁阶段执行器关闭可能引发的 `RejectedExecutionException`，保证恢复流程健壮性。
