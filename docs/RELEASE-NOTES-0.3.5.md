# DiPlay v0.3.5 — 视频恢复与 Surface 复用修复、USB 占用重试收敛及通话音频兼容增强

## 更新

- 视频流中断后先尝试恢复画面，再决定是否重建完整连接；修复恢复期间新画面流已建立、旧超时任务仍可能重新挂起并关闭会话的竞争问题。
- 修复释放解码器时用 Canvas 清屏占用 Surface 的回归，保留同一 Surface 在解码器重建、倒车返回及后续连接中的复用能力。
- 解码器仍在输出时丢弃过期帧，避免积压触发反复整体刷新；倒车返回后重新挂载回退视频视图，促使系统重建其显示面。
- USB 配置选择遇到 EBUSY 时保留一次重试；连续 USB 占用失败达到上限后停止自动重连，提示拔插设备，避免无限循环。增加 NCM 入队、提交及实际成功写入计数，帮助区分软件排队与 USB 传输问题。
- 通话期间临时提高通话音频流音量，结束后恢复原音量和扬声器状态；新增“通话下行走媒体流”实验性选项，默认关闭，下次连接生效。
- 自动断开原生蓝牙的实验性功能优先尝试仅释放 HFP 链路，失败后回退到原有适配器关闭路径。
- 补齐 Android 12 及以上无线启动所需的蓝牙扫描权限；无扫描权限时不让取消扫描步骤阻断 RFCOMM 连接。热点启动诊断记录前台探测进程退出码。

## 验证

- 版本 `0.3.5` / `versionCode 125`，包名 `com.shihab.diplay`，最低 Android 4.2（API 17）。
- 发布前执行项目规定的完整单元测试、Debug Lint 与构建，以及签名、独立运行认证、APK 内嵌源码版本和 SHA-256 校验；实测结果记录在 GitHub Release。
- 增加视频恢复取消竞争、通话下行音频路由隔离回归，以及同一 Surface 连续两次 H.264 解码的 Android 4.4 运行时验证。
- 自动化及模拟器验证不替代实车验收；实体车机、iPhone、CM390、倒车画面和厂商通话音频路由仍需按设备复测。
