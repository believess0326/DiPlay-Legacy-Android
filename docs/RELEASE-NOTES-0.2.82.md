# DiPlay v0.2.82 — T3 / CM390 连接与拔插重连修复

## 更新

- 修复外置 USB 蓝牙 SDP 服务查询中 UUID 序列长度错误，以及 L2CAP 配置应答通道号错误；等待双向配置完成后再查询服务，避免过早发送数据。服务发现失败时保留真实错误，不再猜测 RFCOMM 通道 1。
- 修正 RFCOMM 发起方与应答方的方向位及 C/R 位；对端拒绝连接时不再误报成功。
- 蓝牙认证按 ACL 链路串行处理，认证等待覆盖车机与 iPhone 的配对确认时间；只有认证与加密完成后才继续。外置蓝牙启用时使用该适配器的数据通道，避免失败后误切到 T3 的原生 GOC 音频蓝牙。
- 外置蓝牙配对弹窗加入全部七种语言的标题、说明与倒计时；已有配对项按当前 ACL 链路显示连接状态。
- 连接页与诊断页统一进入同一个蓝牙诊断页面，自动区分外置 USB 蓝牙和原生蓝牙；外置硬件检测结束后恢复无线服务，并提示硬件自检通过不等于 CarPlay 已连接。
- 现有用户态有线网络无需创建系统 VPN，启动时不再请求无关的 VPN 授权；需要 VPN 的路径仍以系统授权结果为准。
- iPhone 拔线后立即中止旧 USB/网络链路，在独立线程清理会话，等待旧控制任务退出后再开始新一轮发现；避免清理任务排在其要结束的控制循环之后。
- 修复网络桥中止后跳过资源释放的问题。USBMUX 与 NCM 关闭等待已有读写退出，设备已拔出时不再释放其接口；忽略旧会话迟到的结束回调，避免干扰重连后的界面。
